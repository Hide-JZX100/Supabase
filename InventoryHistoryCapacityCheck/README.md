# Supabase DB容量監視・閾値超過時メール通知機能 (InventoryHistoryCapacityCheck)

## 概要と目的
本プロジェクトは、Supabase上の `ne_inventory_history` テーブルの物理容量（MB）を定期的にチェックし、あらかじめ設定された閾値（80MB / 90MB / 100MB）を超過している場合に管理者宛てに警告メールを送信するGoogle Apps Script (GAS) スタンドアロンプロジェクトです。

将来的なデータ増加に伴うDB容量の逼迫を早期に検知し、データ退避やメンテナンスのアクションを促すための「セーフティネット」として機能します。

---

## ファイル構成
GASプロジェクト内は以下のファイル群で構成されています。

| ファイル名 | 役割 |
| :--- | :--- |
| `00_Config.設定値.gs` | 閾値、監視テーブル名、無料枠上限等の定数定義および接続情報のロード |
| `01_CapacityChecker.容量取得とRPC呼び出し.gs` | Supabase RPC `get_table_size_mb` を呼び出して容量を取得（指数バックオフによるリトライ機能付き） |
| `02_Notifier.閾値判定とメール通知.gs` | 取得した容量と閾値の比較判定および警告メール送信処理 |
| `03_Trigger.日付判定（防御的チェック）.gs` | メインエントリーポイント `checkCapacityMain()` と、実行対象日の防御的日付判定 |
| `99_Utils.ログユーティリティ.gs` | ログレベルに応じた出力制御、エラーログ、JST日時フォーマットなどのユーティリティ |

## 機能仕様

### 1. 監視対象と閾値
*   **対象テーブル**: `ne_inventory_history`
*   **閾値**: `80 MB` / `90 MB` / `100 MB` の3段階
*   **通知タイミング**: 容量チェック時に現在容量がいずれかの閾値以上であった場合、該当する閾値ごとに個別にメールを送信します（重複排除は行わず、超過した分だけ通知されます。例えば 92MB であれば 80MB・90MB の2通が送信されます）。
*   **無料枠との比較**: Supabaseの無料枠上限である `500 MB` に対する使用率（%）を算出し、メール本文に含めます。

### 2. メール通知先
*   **送信先**: 実行ユーザーのメールアドレス (`Session.getEffectiveUser().getEmail()`)
*   **送信方法**: GmailApp を使用した直接送信

### 3. 防御的日付チェック
*   **実行対象日**: 毎月 **1日、11日、21日、31日** のみ
*   **動作**: トリガーや手動によって関数 `checkCapacityMain` が呼び出された際、実行日（JST基準）の1の位が「1」であるかを確認し、該当しない場合は何も処理をせず即時終了（早期リターン）します。これにより、トリガーの誤設定や手動実行による誤爆を防ぎます。

## 導入手順

### 1. スクリプトプロパティの設定
GASエディタの「プロジェクトの設定」＞「スクリプトプロパティ」に、以下の項目を追加してください。

| プロパティ名 | 設定値の例 | 説明 |
| :--- | :--- | :--- |
| `SUPABASE_URL` | `https://xxxxxx.supabase.co` | SupabaseプロジェクトのURL |
| `SUPABASE_KEY` | `eyJhbGciOiJIUzI1Ni...` | Supabaseの `anon` キー |
| `LOG_LEVEL` | `2` | ログ出力レベル（1: MINIMAL, 2: SUMMARY(推奨), 3: DETAILED） |

### 2. 月次実行トリガーの手動設定
定期的に実行されるよう、GASエディタの「トリガー」メニューから、以下の4つのトリガーを**手動で個別に登録**してください。

#### 設定パラメータ一覧
*   **実行する関数**: `checkCapacityMain`
*   **実行するデプロイ**: `ヘッド`
*   **イベントのソース**: `時間主導型`
*   **トリガーのタイプを選択**: `月ベースのタイマー`

#### 登録する4つのトリガー（日の指定）
1.  **日**: `1日` ／ **時間**: `午前5時〜6時` （他のバッチと重複しない時間帯を推奨）
2.  **日**: `11日` ／ **時間**: `午前5時〜6時`
3.  **日**: `21日` ／ **時間**: `午前5時〜6時`
4.  **日**: `31日` ／ **時間**: `午前5時〜6時`

> [!WARNING]
> **31日トリガーに関する注意点**
> Google Apps Scriptの仕様上、指定した「日」が存在しない月（2月、4月、6月、9月、11月）は、31日のトリガーは実行されません（エラーにもならずスキップされます）。これはGASの制限事項として運用上許容されています。

## テスト・動作確認方法
各モジュールには動作確認用のテスト関数が定義されています。GASエディタ上で対象の関数を選択して実行し、実行ログを確認してください。

1.  **接続プロパティ取得のテスト**: `test_getSupabaseConfig()` (`00_Config.設定値.gs` 内)
2.  **ログ出力機能のテスト**: `test_logUtils()` (`99_Utils.ログユーティリティ.gs` 内)
3.  **Supabase接続および容量取得テスト**: `test_getTableSizeMb()` (`01_CapacityChecker.容量取得とRPC呼び出し.gs` 内)
4.  **閾値判定とメール送信テスト**: `test_checkThresholdsAndNotify()` (`02_Notifier.閾値判定とメール通知.gs` 内)
    *   *※実行するとご自身のアカウント宛にテスト用の警告メールが送信されます。*
5.  **日付判定テスト**: `test_isTargetDay()` (`03_Trigger.日付判定（防御的チェック）.gs` 内)
6.  **全体結合テスト**: `test_checkCapacityMain()` (`03_Trigger.日付判定（防御的チェック）.gs` 内)
    *   *※通常呼び出し（非対象日の場合はスキップされる）と、対象日をシミュレートした強制実行（実際にSupabaseを叩く）の2パターンが検証されます。*
