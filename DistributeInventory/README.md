# DistributeInventory (在庫情報配布システム)

Supabase の `NE_InventoryData` テーブルに蓄積された在庫情報のうち、**有効な商品（`is_active = true`）の差分**を抽出し、指定された複数の社内確認用スプレッドシートに対して、商品コードで紐付けた「上書き更新（存在しない場合は末尾追記）」を行う Google Apps Script (GAS) プロジェクトです。

> [!NOTE]
> ネクストエンジン側で削除・非表示となり、Supabase 側で非活性化（`is_active = false`）された商品は同期対象外となります。すでにスプレッドシートに同期済みの商品を消去したい場合は、手動で `initializeAllSheets`（全件初期化）を実行することで、有効な商品のみに再構成されます。

## ⚙️ セットアップ手順

### 1. スクリプトプロパティの設定
GAS プロジェクトの「プロジェクトの設定」（歯車アイコン）から、以下のスクリプトプロパティを追加してください。

| プロパティ名 | 値の例 | 説明 |
|---|---|---|
| `SUPABASE_URL` | `https://xxxx.supabase.co` | Supabase プロジェクトの URL |
| `SUPABASE_KEY` | `eyJhbGciOi...` | Supabase の anon キー（読み込み専用のため anon key で十分です） |
| `LOG_LEVEL` | `2` | ログ出力レベル（1: MINIMAL / 2: SUMMARY / 3: DETAILED） |
| `TRIGGER_FUNCTION_NAME` | `distributeInventoryChanges` | 定期実行するメイン関数名 |
| `TRIGGER_MODE` | `TOMORROW` | スケジュール設定モード（通常は `TOMORROW` を推奨） |
| `SHEET_CONFIG_1` | `{"id":"スプレッドシートID_A","sheet":"在庫管理"}` | 1番目のスプレッドシートIDと対象シート名（JSON形式） |
| `SHEET_CONFIG_2` | `{"id":"スプレッドシートID_B","sheet":"発注管理"}` | 2番目の設定（以降、連番で複数追加可能） |
| `ERROR_NOTIFICATION_EMAIL` | `admin@example.com` | エラー通知先のメールアドレス（未設定時はメール通知スキップ、カンマ区切りで複数指定可） |
| `API_SHARED_TOKEN` | `任意のランダム英数字` | 送信側(GetInventoryData)と共通で使用する認証トークン |
| `RECEIVER_TRIGGER_DELAY_MS` | `100` | （任意）受信側ワンタイムトリガーの発火遅延時間ミリ秒（未設定時は既定値100ms） |

> [!NOTE]
> `SHEET_CONFIG_X` は `SHEET_CONFIG_1` から始まり、連番が途切れた時点で読み込まれます。
> 途切れた時点で読み込みが終了するため、欠番（例: 1, 3があり2がない）がないように設定してください。

## 🚀 運用方法

### 2. 初回全件初期化（手動実行）
本システムの上書き更新方式は、あらかじめシートに全件データが書き込まれていることが前提（行特定のキーである商品コードが存在している必要があるため）となります。
そのため、最初の実行時は以下の手順を行ってください。

1. GASエディタの関数選択から `initializeAllSheets` を選択します。
2. 実行ボタンをクリックし、手動で実行します。
3. これにより、指定したすべてのスプレッドシートの対象シートがクリアされ、最新の全在庫データがヘッダー付きで一括書き込みされます。
4. 同時に `SUPABASE_LAST_EXECUTED_AT` プロパティに現在時刻が書き込まれるため、次回以降は差分更新として自動動作します。

### 3. スケジュール実行トリガーの設定 (フェイルセーフ)
在庫データ取得側の `GetInventoryData` プロジェクトの処理完了後に連動して動作させるため、固定スケジュール（送信側の5分後）を設定します。動的トリガーによるリアルタイム連携の並行稼働期間中は、この固定スケジュールトリガーは予備（フェイルセーフ）として機能します。

1. スクリプトプロパティの `TRIGGER_FUNCTION_NAME` に `distributeInventoryChanges` が設定されていることを確認します。
2. GASエディタから `setTrigger` 関数を実行します。
3. これにより、以下の時刻に自動実行されるトリガーが設定されます：
   * **0:15** / **8:05** / **10:05** / **13:35** / **16:05** / **19:05** / **21:05**

### 4. Web App の公開と動的トリガー連携 (リアルタイム連携)
送信側からの在庫更新検知に連動してリアルタイムで在庫配布処理を起動するため、Web App を公開して Webhook を受信します。ログ欠落問題を回避するため、`doPost` は動的トリガーを作成して即座に応答を返し、実際の配布処理はトリガー経由で非同期実行されます。

1. **Web App デプロイ**: GAS エディタの「デプロイ」 ➔ 「新しいデプロイ」から種類を「ウェブアプリ」とし、実行ユーザーを「自分」、アクセスできるユーザーを「全員」に設定してデプロイします。
2. **トークン検証**: スクリプトプロパティ `API_SHARED_TOKEN` を設定し、送信側からのリクエストを簡易認証します。
3. **URL登録**: 発行されたウェブアプリのURLを送信側のスクリプトプロパティ `RECEIVER_WEBAPP_URL` に登録します。

## 🧪 テスト・診断方法
`99_Tests.テスト.gs` に定義されているテスト関数を実行し、動作確認を行えます。

1. **`testSupabaseConnection()`**：Supabase との接続およびデータ取得（1件）の確認。
2. **`testSheetConfigs()`**：スクリプトプロパティ設定とスプレッドシート・シートへのアクセス権の確認。
3. **`testLogLevel()`**：ログ出力レベルの切り替えテスト。
4. **`testGetChangedInventory()`**：直近2時間以内の差分データを Supabase から取得するテスト。
5. **`testLastExecutedAt()`**：最終実行日時の往復保存・読み込みおよび復元テスト。
6. **`testBuildRowIndexMap()`**：スプレッドシート上の `Map<商品コード, 行番号>` の生成テスト。
7. **`testUpdateInventoryRows()`**：テスト用差分データによる既存行の上書き・新規行の追加テスト（書き込み後に値が正しいか自動で整合性検証も行います）。
8. **`testInitializeSheet()`**：ダミーデータを用いたシートの全件クリア＆初期化書き込みテスト。
9. **`testFullFlow()`**：差分取得からスプレッドシート書き込み・実行日時の保存までの一連の統合テスト。
10. **`testSendErrorMail()`**：登録された管理者用メールアドレスへのテストメール送信確認。
11. **`testIsActiveFiltering()`**：取得データに `is_active = false` のデータが含まれていないことの検証。
12. **`testWebhookReceiver()`**：Webhook受信 (`doPost`) およびトークン認証の動作検証。

## SRE（運用・安定化）的視点
* **動的ワンタイムトリガーによる非同期化とログ記録**: `doPost` 受信時に即座に動的トリガーを作成してレスポンスを返却し、実際の在庫配布処理はトリガー経由の非同期実行（`triggeredDistributeInventory`）としました。これにより、`doPost` の実行制限時間（30秒）によるタイムアウトを回避しつつ、GASの「実行数」パネルに完全な詳細ログを記録できるようにしました。
* **一括書き込みによるAPI削減と高速化**: 行ごとの個別書き込みを廃止し、メモリ上で既存行と新規行のデータをマージした上で、1回の `setValues` で一括書き込みを行うよう改善しました。これにより、同期の実行速度が劇的に向上し（例：342件の更新で38.7秒から8.4秒に短縮）、GASの実行時間上限（6分）の回避とGoogle APIクォータの消費低減を両立させています。
* **管理者へのエラー即時メール通知**: スプレッドシートごとの更新エラーや、バッチ全体の致命的なエラーが発生した際に、スクリプトプロパティに登録されたメールアドレス宛に即時エラー内容を送信します。エラーログシートに書き出すだけでは気づきにくいシステム異常を早期発見できます。
* **エラーハンドリングの局所化**: 複数スプレッドシートを処理する際、特定のシートで書き込みエラー（権限不足やシート消失等）が発生しても処理を中断せず、エラー内容をバッファリングした上で他のシートの更新処理を継続します。
* **各シートでのエラーログ自己完結**: エラーが発生した場合は、対象スプレッドシートに「エラーログ」シートを自動生成し、エラー内容を直接書き込みます。これにより、シートの管理者がエラー発生をすばやく検知できます。
* **不要な更新の抑制**: Supabase から取得した差分レコードが 0 件のときは、スプレッドシートへのアクセスおよびスクリプトプロパティの更新を行わずに早期リターンします。Google 側の API クォータ（割当量）の消費を最小限に抑えます。
* **LockService による多重起動防止**: 動的トリガー（Webhook呼び出し）と固定時刻トリガーが同時に実行されスプレッドシート書き込みが競合するのを防ぐため、`LockService` による排他制御を導入しました。ロック取得ができない場合は実行を自動的にスキップします。
