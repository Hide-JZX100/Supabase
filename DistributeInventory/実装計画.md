# DistributeInventory プロジェクト 実装計画

## 概要

Supabase の `NE\_InventoryData` テーブルから差分データを取得し、
社内在庫確認用スプレッドシートに「商品コードで行を特定して上書き更新」する
新規 GAS プロジェクト **DistributeInventory** を構築します。

\---

## 確定した仕様（ユーザー回答より）

|項目|決定内容|
|-|-|
|書き込み方式|差分データを「上書き更新」（商品コードで行を特定して該当行のみ更新）|
|書き込み先スプレッドシート|当初は1枚（社内在庫確認用）|
|フィルタ|当初は不要|
|実行タイミング|独立トリガー（GetInventoryDataの約5分後を想定）|
|ログ管理|スクリプトプロパティで指定したシートID毎にエラーログシートへ書き込み（シートなければ自動作成）|

\---

## 未確認・確認事項

> \[!IMPORTANT]
> \*\*書き込み先スプレッドシートに既存データがない場合の初期化方法\*\*
>
> 「上書き更新」方式では、対象スプレッドシートに商品コード付きの全件データが
> 事前に存在している必要があります（商品コードで行を特定するため）。
> 以下のどちらにするか教えてください：
>
> \*\*案A（推奨）\*\*: 初回のみ「全件書き込み」で初期化する関数を別途用意する。
> それ以降は差分更新のみ動作する。
>
> \*\*案B\*\*: 毎回「全件取得・全件書き直し」にする（シンプルだが差分取得の恩恵が薄い）。

> \[!NOTE]
> \*\*スプレッドシートのシート名について\*\*
>
> `SHEET\_CONFIG\_1` のスクリプトプロパティに設定する「シート名」は
> 書き込み先シートの名前です（例：「在庫一覧」「在庫管理」など）。
> 既存スプレッドシートのシート名を確認の上、設定してください。
>
> また、書き込み先スプレッドシートIDも事前に確認が必要です。

実装をスモールステップで進めるため、以下のフェーズに分割します。

### Phase 4: メイン処理・テスト（Phase 1〜3に依存）

`10\_Main`, `99\_Tests`, `トリガー設定.gs` を作成・動作確認。

## 各ファイルの詳細設計

### Phase 1: 基盤ファイル

#### \[NEW] 11\_Config.設定管理.gs

GetInventoryDataの `11\_Config.gs` をベースに DistributeInventory 用に改修。
NE API 関連定数を削除し、スプレッドシート設定取得を新規追加。

**定義する定数・関数：**

|名前|種別|内容|
|-|-|-|
|`LOG\_LEVEL`|const|MINIMAL/SUMMARY/DETAILED|
|`RETRY\_CONFIG`|const|MAX\_RETRIES=3, ENABLE\_RETRY=true|
|`DISTRIBUTE\_COLUMNS`|const|A〜M列の列番号定義（13列）|
|`INVENTORY\_SHEET\_HEADERS`|const|ヘッダー行配列（13列分）|
|`getSheetConfigs()`|function|スクリプトプロパティから `SHEET\_CONFIG\_1`, `SHEET\_CONFIG\_2`... を全件取得してJSON解析した配列を返す|

**スクリプトプロパティ（DistributeInventoryに設定するもの）：**

|キー|値の例|説明|
|-|-|-|
|`SUPABASE\_URL`|`https://xxxx.supabase.co`|Supabase URL|
|`SUPABASE\_KEY`|anon key|Supabase anon key|
|`SUPABASE\_LAST\_EXECUTED\_AT`|ISO文字列|自動保存|
|`LOG\_LEVEL`|`2`|ログレベル|
|`TRIGGER\_FUNCTION\_NAME`|`distributeInventoryChanges`|トリガー対象関数名|
|`TRIGGER\_MODE`|`TOMORROW`|トリガーモード|
|`SHEET\_CONFIG\_1`|`{"id":"SSID","sheet":"在庫一覧"}`|書き込み先設定|

### Phase 2: 差分取得

#### \[NEW] 14\_SupabaseRepository.差分取得.gs

GetInventoryData の `17\_SupabaseRepository.gs` から差分取得関連のみを抽出・流用。

**実装する関数：**

|関数名|内容|
|-|-|
|`getChangedInventorySince(since)`|指定日時以降に更新された商品を取得|
|`saveLastExecutedAt()`|最終実行日時を保存|
|`loadLastExecutedAt(fallbackHours)`|最終実行日時を読み込み（未設定時はfallback）|

### Phase 3: シート書き込み

#### \[NEW] 15\_SheetRepository.シート書き込み.gs

**DistributeInventory 独自の新規実装。**

書き込み方式は「差分上書き更新」：商品コードで既存行を特定し、該当行のみ更新する。

**実装する関数：**

|関数名|内容|
|-|-|
|`buildRowIndexMap(sheet)`|シートのA列全件を読み取り `Map<商品コード, 行番号>` を生成|
|`updateInventoryRows(sheet, changedData)`|差分データで既存行を上書き更新。商品コードが見つからない行は末尾に追記|
|`initializeInventorySheet(sheet, allData)`|初回のみ全件を書き込む初期化関数（初期化用）|
|`logErrorsToDistributeSheet(sheetId, errorDetails)`|指定スプレッドシートIDのエラーログシートに書き込む|

**`updateInventoryRows` の処理フロー：**

```
1. buildRowIndexMap(sheet) で商品コード→行番号のMapを生成
2. changedData をループ
   a. 商品コードが Map に存在 → 既存行（A〜M列）を setValues で更新
   b. 商品コードが Map にない → 末尾に追記（新商品対応）
3. 更新件数・追記件数をログ出力して返却
```

**書き込み列定義（13列）：**

|列|項目名|Supabase フィールド名|
|-|-|-|
|A|商品コード|商品コード|
|B|商品名|商品名|
|C|在庫数|在庫数|
|D|引当数|引当数|
|E|フリー在庫数|フリー在庫数|
|F|予約在庫数|予約在庫数|
|G|予約引当数|予約引当数|
|H|予約フリー在庫数|予約フリー在庫数|
|I|不良在庫数|不良在庫数|
|J|発注残数|発注残数|
|K|欠品数|欠品数|
|L|JANコード|JANコード|
|M|更新日時|更新日時|

### Phase 4: メイン・テスト

#### \[NEW] 10\_Main.エントリーポイント.gs

**メイン関数 `distributeInventoryChanges()`：**

```
Step 1: loadLastExecutedAt() で前回実行日時を取得
Step 2: getChangedInventorySince() で差分データを取得
        → 0件の場合はここで終了
Step 3: getSheetConfigs() で書き込み先リストを取得
        → 各スプレッドシートに updateInventoryRows() で書き込み
Step 4: saveLastExecutedAt() で今回の実行日時を保存
Step 5: 実行サマリーをログ出力
```

**エラー処理方針：**

* Step 2 の Supabase 接続エラー → 全体終了（`throw` で再スロー）
* Step 3 の特定シート書き込みエラー → そのシートをスキップして他のシートは続行

## 検証計画

### 自動テスト（GASエディタで実行）

```
1. testSupabaseConnection()  → Supabaseに接続できるか確認
2. testGetChangedInventory() → 差分データが取得できるか確認
3. testSheetConfigs()        → スクリプトプロパティが正しく設定されているか確認
4. testBuildRowIndexMap()    → シートの行番号マップが生成できるか確認
5. testUpdateInventoryRows() → テスト用SSに正しく書き込まれるか確認
6. testFullFlow()            → 全体フローが正常に動作するか確認
```

### 手動検証

1. テスト用スプレッドシートで `testFullFlow()` 実行 → シートの更新を目視確認
2. `setTrigger()` を実行してトリガー設定を確認
3. トリガー実行後にシートが正しく更新されていることを確認

## 開発上の注意点

> \[!WARNING]
> \*\*初回は全件データが必要です\*\*
>
> 「商品コードで行を特定して上書き更新」する方式では、
> 対象シートに最低限 A 列（商品コード）のデータが必要です。
> 初回のみ `initializeInventorySheet()` を手動実行してから
> 通常の差分更新トリガーを設定してください。
>
> 初期化方法については確認事項（上記）の回答後に決定します。

> \[!NOTE]
> \*\*GetInventoryData との実行タイミング\*\*
>
> GetInventoryData（在庫差分更新）の実行時刻は 8:00, 10:00, 13:30, 16:00, 19:00, 21:00。
> DistributeInventory のトリガーはこれらの約5分後（例: 8:05, 10:05...）を推奨します。
> ただし今回は「独立したスケジュール」のため、`setTrigger()` で設定する
> `executionTimes` 配列をその時刻に合わせて変更します。
